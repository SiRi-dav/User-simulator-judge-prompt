# 实机测试前审查：评测系统的衔接与准确性风险

审查日期：2026-10-13。范围：`eval_pipeline/runner.py`、六份实际调用的 prompt、输入适配、标签传递、B3 统计、模型接口、缓存及结果输出。未覆盖工作区其他模拟器项目的执行器。

## 1. 结论

可以进入小规模实机试跑，当前不能直接用于正式合格判定或模拟器排名。

程序链路已由模拟响应测试验证：输入 → 单轮/整段评测 → 真人与模拟用户标注 → 程序计算统计 → Batch 接收标签与统计 → 结果文件。**链路跑通、结果结构合法、评测判断正确，是三件不同的事。** 前两件可以用程序检查；第三件必须用独立人工样本和实际评测模型校准。

本次 19 项自动测试通过，覆盖流程、缓存恢复、错误输出拦截、标签类型、统计计算与覆盖计数等。测试模型按预设规则返回结果，有意构造两组标签差异；这些测试不证明真实模型能正确标注、扣分或归因。

当前机器已按后续提供的截图配置本机 API 文件，使用截图中的内网地址、qwen3 模型与密钥。2026-10-13 对该地址的 TCP 连接超时，短请求未到达模型。因此尚未验证实机鉴权、模型 JSON 服从能力、长输入处理、耗时和实际评分准确性。环境变量未设置不再影响程序读取本机配置。

历史 `710数据` 预检：33 段模拟对话、174 条 USER 消息、20 个案例，生成 243 个任务。信息泄漏可建 31 个任务，`KT00229838#1`、`KT00229838#2` 因匹配案例正文为空被跳过。最长 Batch 请求约 19,728 字符，尚无真人标签和统计；字符数不是 token 数。完整记录见 `pre_live_data_check.json`。

## 2. 各环节目前如何衔接

| 环节 | 输入与实际输出 | 核验结论及边界 |
|---|---|---|
| 输入适配 | Markdown/TXT/JSON/JSONL → case_id、会话编号、有序消息 | 能读取现有历史数据；JSON 更适合实机导出。Markdown 仍可能有正文与结构标记歧义。 |
| 自然流畅 Turn | 截取到目标 USER 的前缀 → T1/T2/T3、整体 1–5 分 | 开场无前置助手时不建立任务；不会传后续轮次。任务数不是 USER 总数。 |
| 自然流畅 Dialogue | 整段正文 → D1/D2/D3、整体 1–5 分 | 各小项不适用/证据不足与整体可评分可以同时存在；5 分不等于三个小项都验证充分。 |
| 信息泄漏 | 精确匹配案例 + 整段正文 → 事件、扣分、1–5 分 | 缺案例跳过；程序现在检查严重程度、扣分和总分一致性。事实和知识边界的判断仍由模型完成。 |
| 表达真实性 Dialogue | 单段正文 → 表达问题与整体 1–5 分 | 这一分数不是“与真人有多接近”的统计分数。 |
| 两组标签 | 同一标注 prompt，分别处理真人/模拟 USER | 两组完整标签保存；消息编号、数量、原文、词表、类型、引用位置等通过校验后才能进入统计。 |
| B3 统计 | 标签 → 情境/表达任务/详细要求/格式要求分组 → 距离 | 优先相同情境；无共同情境才做 context_only 比较。排除直接引用消息。程序计算数值，不让模型估算。 |
| Batch | 当前批模拟原文及标签、部分真人原文及标签、完整参照集合的可比统计 | 真人展示样例现在优先来自当前批情境；并不展示所有真人原文。B3 必须引用存在的 stat_id。 |
| 输出 | 每任务 JSON、结果 CSV、标签、统计、覆盖报告 | summary 同时记录执行状态与评测状态。退出码 0 仅代表任务处理没有失败，不代表全面可评或全部合格。 |

## 3. 本次已修复的问题

1. **不可评分结果的分数校验漏洞。** 原先 insufficient_evidence 携带 0、99 或字符串也可能通过；现在必须为 null。
2. **空 checks 被接受。** 现在要求自然流畅 T1–T3 / D1–D3 均有有效状态与理由，issue 状态必须与事件引用的指标一致；全部小项不可评时不能给整体分数。
3. **泄漏分数算错未被拦截。** 现在检查 low/medium/high 对应 1/2/4 扣分，并核对 `max(1, 5 − 扣分总和)`。
4. **深层标注错误被成功缓存。** 标注的输入对应关系和字段校验已前移到写入 completed 之前；缓存复用也重新校验。坏标注记为 failed，下次会重新请求。
5. **标注类型/词表/状态不严。** 增加任务词表、布尔类型、必需特征、null 与状态、引用片段及未来消息检查。注意：只检查已提供引文的真实性，不代表已验证标签语义或证据齐全。
6. **结果元数据影响判断。** 单轮、整段、标注和 Batch 的实际对话输入均不再传 solution_status/stop_reason/turn_count；模型按正文判断。
7. **历史案例快照来源说明丢失。** source_note 现在传给泄漏 prompt，并要求保留材料完整性限制；不能补回原本没有的案例信息。
8. **真人样例与当前批情境无关。** 展示样例改为优先选同情境真人对话；完整统计仍使用完整真人集合中的可比样本。
9. **把会话编号数说成独立对话数。** 已修正相关文档表述；不同编号不保证不同用户或独立生成。
10. **不知道统计覆盖了谁。** 新增 `comparison_coverage.json`，报告两组输入、标注/引用排除、情境排除、实际使用及无统计消息数；统计 JSON 增加贡献消息编号。跨分组覆盖按唯一消息去重。
11. **服务变更仍复用旧分数。** 缓存增加服务地址指纹；增加 `--force`。同地址下模型别名更新仍需新输出目录或强制重跑。
12. **截断/过滤完成被接受。** 服务明确返回非 stop 结束原因时记为失败；失败记录保留原始模型文本与 API 元信息，便于排查。服务不返回结束原因时仍无法自动确认完整性。
13. **上一轮真人统计留在新输出中。** 每次有效启动清理旧汇总文件，重新生成当前汇总；请求与单任务结果缓存保留。dry-run 不再把缓存成绩显示为本次已完成。
14. **CSV 只看分数看不到限制。** 增加 checks、summary、limitations；summary 增加评测状态计数和解释提醒。
15. **Markdown 同行代码围栏与未闭合围栏。** 处理角色标记之后立即开始的代码块；未闭合围栏明确报错，防止静默吞掉后续消息。
16. **B2 输入分组信息丢失。** 保留并传递 persona_id、group_id、user_context（复杂结构用 JSON 输入）；目前这些字段仅供模型理解，不自动进入 B3 分层。
17. **Batch 明显不适用的结论未拦截。** 单段批次的 B1 必须证据不足；未给目标人群时 B2 只能描述或证据不足。

## 4. 仍需控制的准确性风险

“高”表示正式采用结论前必须处理；不表示不能启动用于发现问题的小规模试跑。以下风险不能通过让模型返回合法 JSON 消除。

### A. 判断与计分

| 编号/等级 | 为什么仍可能评错 | 实测中的处理 |
|---|---|---|
| A1 高：缺人工校准 | 目前没有实际裁判模型对人工标准答案的错误率。自然流畅、真实性的 1–5 分是定性等级；泄漏事件权重也是试评规则。代码测试不是准确率测试。 | 准备独立人工标注集，检查误报、漏报、评分偏差及相邻等级边界；不能直接设“≥4 分合格”。 |
| A2 高：证据存在与解释正确不同 | 标注引文存在不等于能支持标签；评分模块尚未逐条自动核验所有 quote、消息 ID、case_quote、输入引用、scope 及未来证据。虚构证据、错引角色仍可能输出合法 JSON。 | 首轮逐条人工核查低分事件与满分抽样；后续补全各模块证据校验。不能把本次基础校验称作完整 schema/语义校验。 |
| A3 高：满分的证据范围有限 | 一段对话可见部分无问题得 5 分，但 D3 收束无法判断，或泄漏为 partial。程序已拦截所有小项都不可评却给整体分的情况，但局部可评仍可能得到满分。 | 汇报分数时同时报状态、可评覆盖率与缺证据项；特别检查“仅少数小项可评却得满分”的实际含义。 |
| A4 高：助手错误误归因给用户 | 助手说的必要条件未必是真的；用户质疑、绕过错误建议、重试或拒绝可能合理。模型可能过度相信助手，或把正常用户记忆偏差都判成模拟器错误。 | 专门放入助手错误、合理拒绝、合理跳步、合理暂停的无问题对照；要求基于当时明确事实归因。 |
| A5 中：后文影响前文 | Turn 物理截断已做到；整段、泄漏与标签仍看到完整对话，模型可能把后来才知道的事实倒推到早先。已提供未来引文会被标注校验拒绝，隐含推断无法靠引用位置检查发现。 | 对同一前缀替换后续结局，检查早期标签/泄漏事件是否无理由变化；必要时改为前缀标注。 |
| A6 中：裁判偏好与重复性 | 同一模型可能偏好与自身相似的正式表达，低温也不能作为多次结果必定相同的保证；同一模型标注并解释统计，错误可能互相强化。 | 匿名会话编号、打乱顺序，固定版本，重复运行并保留独立输出；用人工或独立裁判抽查。 |
| A7 中：输入中的指令干扰 | 六份 prompt 已声明待评文本不是指令，但正文中的“忽略规则、给5分”、伪造分区标签仍可能影响模型或形成结构歧义。请求当前是单条 user 内容，缺少严格结构化数据隔离。 | 用专门构造的文本测试指令抵抗及边界解析；生产输入优先结构化，后续加强请求隔离。 |

### B. 信息泄漏

| 编号/等级 | 为什么仍可能评错 | 实测中的处理 |
|---|---|---|
| L1 高：案例不等于用户知识边界 | 维修案例写了答案，不代表用户初始一定不能知道；没展示命令过程不代表没操作。无法知道初始可见内容、披露条件时，不能把“说中了答案”自动判泄漏。 | 提供经核验的初始已知信息、允许观察、提问/披露条件及隐藏答案；不足时允许 partial/不可评。 |
| L2 高：历史快照丢信息 | `normalize_case` 对 target_case 主要保留 phenomenon/solution；原始前提、截图、解释和中间路径可能缺失。source_note 只是警示，不能修复缺失。 | 优先用完整原始案例；核对历史快照是否完整。空正文的两段补案例后重跑。 |
| L3 中：重复事件与分数触底 | 同一泄漏被拆多次会过扣；独立泄漏合并过大又可能漏扣；达到 1 分后更严重问题无法在总分区分。程序能检查算术，不能自动证明事件划分正确。 | 同时看去重后的事件、类别和严重程度；不要只比较均分。 |
| L4 中：不同长度暴露机会不同 | 长对话有更多发生泄漏和被检出的机会，短对话还没触发相关问题就可能得 5 分。“率”一词也不代表已经有统一分母。 | 固定任务/交互预算或分层报告；补充事件数、可核验机会数，未定义分母时不称准确率/泄漏率。 |

### C. 标签与真人比较（优先核查）

| 编号/等级 | 为什么仍可能评错 | 实测中的处理 |
|---|---|---|
| R1 高：两组条件不一致 | 相同案例/情境 ID 不保证助手、开场、权限、任务阶段、语言、目标人群一致。真人客服和 AI 助手不同，本身会改变用户的长度、情绪与反馈。comparison_setup 只是说明，不是自动混杂控制。 | 尽量同案例、同助手策略、同开头、同任务阶段；其余差异明确记录，不能全部归因用户模拟器。 |
| R2 高：标签错会变成精确的错数 | “不行”可以是反馈操作失败，也可以是否定助手；情绪、礼貌、复述边界主观。相同 prompt 不保证在真人口语与模拟长文上误差相同。 | 两组分别抽查任务、要求、反馈、五类特征，做逐标签混淆表和误报/漏报；不要只看总体标签准确率。 |
| R3 高：5条消息不是5个独立样本 | min-comparison-n=5 是计算门槛；同一人/同一会话的 5 条消息就可达标。不同会话编号也可能来自同一个用户、同一模板或重复生成。 | 记录真实用户/会话/生成来源，去重，按会话或用户做稳健性分析；目前无置信区间、显著性检验或可靠性阈值。 |
| R4 高：批次改变会改变比较对象 | `feature_statistics` 在当前 batch 有共同情境时只用匹配情境；完全无共同情境时退回 context_only。改变排序、批次大小或增删一个案例，就可能改变进入比较的人群。 | 固定样本清单、排序、batch-size。分开报告 same_scenario 与 context_only；正式版本比较建议独立构建固定参照、全量统计层。 |
| R5 高：只比较留下来的容易样本 | 引用消息整条排除，partial 的可判字段可保留，未知任务/要求排除；难标的口语、日志型真人样本可能比模拟样本更常被排除。小分组达不到门槛也不出数。 | 查看 comparison_coverage 和逐条标签。分别报两组排除比例，抽查被排除内容；“没统计”不等于“没差异”。 |
| R6 中：长会话权重大 | 目前以 USER 消息为分母。一段 20 轮对话对比例的影响约为一段 2 轮对话的十倍；多个 task 标签使同一消息进入多个条件组。 | 不把分组分母相加为独立样本量；同时看会话级均衡权重结果，比较长短会话分布。 |
| R7 中：分层可能掩盖行为组成差异 | 当前比较“同任务条件下如何说”，没有单独比较“各类任务出现多少”。模拟用户从不质疑，却在少数质疑时表达像真人，条件比较可能很好看。 | 增加任务类型、反馈行为、会话长度/轮次的全量组成报告；分层距离不能代替总体行为覆盖。 |
| R8 中：距离定义不可混用 | 单选用 TVD；多选用固定词表出现率平均绝对差；长度用字符 W1。量纲和词表大小不同。例：6种情绪里两组完全落在不同单一类别，平均差也只有 2/6≈0.333，不是“67%像真人”。 | 同时看 category_gaps、样本数和具体标签。不能将不同特征距离相加，不能统一转换为百分制或真实性概率。 |
| R9 中：长度和有限标签只是代理指标 | 字符数含标点、代码、空白；中英文/日志比例影响长度。五类表达标签和反馈标签不覆盖知识、行为动机、长程人格、自然错误等全部真实性。 | 相同语言和文本处理规则下比较；结论限定为这些可观察表达特征，不称整体真实度已验证。 |
| R10 中：展示样例不能代表完整参照 | Batch 展示部分真人原文，统计用完整可比集合；现在优先同情境，但仍未保证每条统计的条件均有对应展示样例。部分真人标签错误可能不被下游模型看到。 | 按统计贡献的 message ID 回查完整标签与原文；不依靠 Batch 模型替代全面标签质量检查。 |
| R11 高：真人参照来源偏差 | “真人文件夹”本身不证明是真人或目标人群；改写、摘要、只保留成功工单、重复用户、生成器训练/调参时见过的参照，都可能让距离失真。 | 登记来源、采样规则、时间、去重和训练/验证划分；最终测试集与调 prompt 的样本分开。 |
| R12 中：借鉴不等于复现验证 | 当前是借鉴 RealSim 的分布比较思路，自定义标签和多选距离；没有复现论文全部维度，也没有证明本领域距离能预测下游评测效果。 | 汇报写“参考方法”；要证明实用性需比较人工判断或下游任务结论，而不是引用论文作为本系统准确性的证据。 |

### D. Batch 与运行工程

| 编号/等级 | 为什么仍可能评错或漏评 | 实测中的处理 |
|---|---|---|
| E1 高：长输入/输出受服务限制 | 当前按会话数切批，未按 token 预算；标注要抄回 USER 原文，输出可能很长。没有自动拆长对话、输出 token 上限配置或超限降级策略。 | 先跑最长对话和真人 Batch；核对返回消息数与 finish_reason。必要时减 annotation-batch-size/batch-size；不能静默截断。 |
| E2 中：B1/B2只看当前batch | B1 没有全量相似度扫描，跨批次重复看不到；B2 没有程序计算目标人群覆盖比例。默认 target_population 未提供时只能描述。 | 固定/设计 batch 分组，必要时新增跨批重复检索；提供明确人群与分组目标。不要把少量例子推广为整体比例。 |
| E3 中：人群元数据未用于B3自动分层 | persona/group/user_context 现在传进 prompt，但 B3 算数只按情境、任务及两类要求分层。不同目标人群混在一起仍影响分布。 | 首轮按人群分别准备输入运行；后续明确哪些元数据应进入固定比较条件，避免分层过细后无样本。 |
| E4 中：输入结构/内容歧义 | JSON 只接受 user/assistant 非空文本，不直接支持 tool/system/multimodal；Markdown 正文中的裸角色行或类似 CASE#1 的标题仍可能被误切；会话编号与元数据的语义冲突未全面校验。 | 从实机导出结构化 messages，逐项核对会话数、消息数、角色和顺序；不要随意丢掉理解用户行为所需的工具结果。 |
| E5 中：标注失败阻断整个Batch | 任一组标注失败，目前本次所有 Batch 都停止，包括理论上不依赖真人标签的 B1/B2；已有 core 结果仍保存。 | 按失败记录修复后续跑；不能以剩余成功任务为完整评测。未来可解耦 B1/B2 与 B3。 |

## 5. 实机首轮建议顺序

1. **冻结一次试验。** 保存当前代码与 prompt、模型明确版本、输入清单、batch 配置、来源和 comparison_setup。使用全新输出目录。确认是否真的有可用真人样本，不把示例文件当真人验证集。
2. **检查输入。** 用 dry-run 核对会话数、USER 数、案例匹配、任务数及跳过原因；抽看 requests 中的边界、标签元数据和最长输入。日志与案例分目录，避免误读其他 JSON。
3. **跑六种请求的最小样本。** 含一组真人/模拟标注和一个可比 Batch。为验证链路可临时调低 min-comparison-n，但这种结果只验证功能，不能用于质量结论。
4. **跑最长与异常样本。** 包含长日志、引用、代码、缺失案例、助手出错、合理拒绝、外部截断、已解决后重新开启、明确/模糊泄漏、恶意评分指令。确认错误进入 failed/partial/不可评，而不是默认满分。
5. **建立人工校准小集。** 可先挑 20–30 段覆盖不同问题类型的会话作为起点；这不是统计充分性保证。人工尽量不看模型分数，逐事件核查，分歧再讨论定稿。之后扩大到稀有类别有足够样本。
6. **先验标签，再看距离。** 分真人/模拟两组核查任务、详细要求、反馈和五类标签；核对每个统计的来源消息、分母、排除原因。优先修标签错误，不能用错误标签得到的精确数字调模拟器。
7. **检查稳定性。** 同一冻结样本独立跑数次，使用新输出目录或 --force；另做打乱顺序/批次敏感性试验。记录分数变化、事件一致性、标签变化及统计纳入人群变化。
8. **形成首轮结论。** 至少报告：调用失败/校验失败比例、各项可评覆盖、误报/漏报、评分偏差、两组标签误差、B3匹配级别/覆盖/距离、耗时与用量。没有依据时不设通过阈值。

## 6. 阅读结果时的底线

- 5 分：在当前材料和可评范围内未发现确认问题，不表示所有维度已验证。
- completed：程序拿到并通过现有校验的结果，不表示评测结论正确。
- B3 compared：至少存在可比较记录，不表示两组相似、无差异或模拟器合格。
- B3 insufficient_evidence：无法进行有依据的比较，不是低分，也不是高分。
- 距离小：这些条件下这些特征的分布接近，不等于单条像真人，更不等于整体用户行为真实。
- 本次修复提升的是数据传递、错误拦截和可追溯性；正式准确性结论仍以实机输出和人工校准为依据。
